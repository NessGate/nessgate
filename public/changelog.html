Changelog

Notable changes to the NessGate resolver and its specification, newest first. Specification stability guarantees live in the specification.

2026

v1.4.0 — Organization Discovery

  • GET /explore/{domain}?org=1 (opt-in). Many organizations publish their machine-readable resources on a related subdomain (developers.openai.com) rather than the apex. Organization Discovery probes a bounded set of plausible same-registrable-domain hosts — subdomains the homepage itself links to, plus a small conventional shortlist (at most 4 hosts × 2 paths) — and reports only resources that actually verify, labelled evidence same-domain-host with the probe provenance. Shared DNS control implies the organizational relationship; it is not independently verified. Hosts probed appear in orgChecked. No brute-force scanning; off by default; /discover and default /explore unchanged.

v1.3.3 — Documentation

  • Corrected the npm package README: current mechanism list, accurate export names, browser guidance (use the hosted endpoint for arbitrary domains), and the optional GB/Z 185.5 gateway option. No behavior change.

v1.3.2 — Evidence-based exploration; version alignment

  • GET /explore/{domain} (additive). Everything /discover returns, plus bounded delegated discovery: NessGate follows the explicit machine-readable pointers a domain declares (an llms.txt index's links, ARD and api-catalog entries) up to depth 2 — cross-host only where the publisher named the target — and federates the official MCP Registry for the domain's verified reverse-DNS namespace. Every record carries an evidence class (publisher-hosted / publisher-declared / namespace-verified / candidate) and a provenance chain. Strictly bounded (depth ≤2, ≤8 hosts, ≤24 requests, global byte cap, SSRF checks on every hop); stateless; no crawling, no guessed subdomains, no ownership claim. /discover is unchanged.
  • Opt-in candidate verification. POST /explore/{domain} with {"candidates":[…]} verifies caller-suggested URLs (from the caller's own AI or search) and labels each evidence:"candidate" — existence and type confirmed, relationship to the domain unverified. NessGate itself runs no AI.
  • Honest empty results. An empty answer now reads "no supported resources found on this exact host", noting that related product hosts or external registries may publish more.
  • Version labels aligned across the library, MCP server, registry listing, and this API description. No behavior change.

v1.3.1 — Accuracy fixes

  • AID, not DNS-AID. The DNS adapter reads the AID draft's TXT record (v=aid1 at _agent); it is not the IETF DNS-AID draft (SVCB at _agents), which is a separate, unimplemented mechanism. The adapter id changed from dns-aid to aid.
  • ARD scope narrowed. NessGate implements ARD's normative domain resolution (well-known catalog + rel="ard", both MUST in v0.91) plus the robots Agentmap: surface; in-page JSON-LD and the not-yet-specified DNS mechanism are not read.

v1.3.0 — GB/Z 185.4 agent descriptions

  • GB/Z 185.4 (China, 智能体互联). ACS agent descriptions are recognized by content and normalized (source gbz-185-4), preserving aic, provider, security schemes, certificate, and skills. No GB/Z-specific path is guessed. The embeddable library adds an optional, Node-only GB/Z 185.5 gateway query against a caller-configured endpoint with caller-supplied authentication.

v1.2.0 — Universal resolver: adapter architecture

  • Fourteen adapters over four channels (well-known paths, the ARD rel="ard" link, the robots Agentmap: directive, and a DNS TXT lookup): adds ANP agent descriptions, UCP merchant profiles, the AID TXT record, and the two additional ARD surfaces to the original set. Listed in the official MCP Registry as com.nessgate/nessgate.

v1.1.0 — Initial public release

  • The neutral resolver. GET /discover/{domain} reads whatever a domain publishes across the supported machine-discovery locations (ARD / ai-catalog.json, A2A agent card, llms.txt, RFC 9727 api-catalog, ai-info.json, OpenAPI, Open Resource Discovery, host-meta) and returns one normalized answer, with a link back to each source so an agent can read the domain directly. NessGate reads these; it does not define or replace them.
  • Embeddable library. A dependency-free resolver at /resolver.mjs and on npm as @nessgate/resolver, running in browsers, Node, Deno, Workers, and agent runtimes with no runtime dependency on nessgate.com. The same lookup is available as the discover_domain MCP tool at /mcp.
  • Open and neutral. Open specification, Apache-2.0 reference implementation, governed by the Charter: free forever, neutral, no accounts, no ranking, no lock-in, stores nothing.
