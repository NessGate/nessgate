## Weakness discovered (the point of the ruler)

**Large OpenAPI specs are missed.** vercel.com `/openapi.json` = 10.8 MB and posthog.com = 6.5 MB
both exceed the resolver's 1 MB `maxBytes` cap → skipped (the only 2 recall misses). Actionable fix
for a later milestone: raise the cap for OpenAPI, or validate the `openapi`/`swagger` field from a
streamed prefix before enforcing size. **Per the corpus rule, that fix will add a regression
fixture** (a resolve-level size case). Recorded as a deviation in `compat/matrix.json` now; not fixed
in M1 (M1 changes no behavior).

## M1 — compatibility corpus + CI spine

- `compat/matrix.json` — 13 protocols, 17 protocol-versions; the source of truth for "supports X".
- `compat/adapters/*.json` — 14 adapter contract manifests (surfaces, versions, authority,
  `canEstablishAuthority`, provenance requirement, deviations, fixtures).
- `compat/fixtures/**` — **21 fixtures** (14 positive + 7 reject), backfilled from the resolver's
  existing normalization tests; includes 1 real-world reject (ucpchecker UCP catch-all).
- `compat/metrics.json` — generated engineering metrics (no confidence scores).
- `scripts/test-compat.mjs` (layer 2 runner, 35 checks) + `scripts/compat-matrix.mjs` (consistency +
  metrics). Both wired into `npm run check` **and the pre-deploy gate** (`scripts/deploy.mjs`).
- CONTRIBUTING rule added: **every compatibility fix must add a permanent regression fixture.**

## CI invariants now enforced

- Regression + v2-alpha + compatibility-corpus + matrix-consistency all gate deploys.
- Matrix ↔ adapter-manifest ↔ fixture consistency (a "supports X" claim without a fixture fails).
- Reject fixtures prove catch-alls / HTML shells / wrong-shape JSON are refused.
- The frozen unseen benchmark is the separate moat ruler; M1 re-run = **67/69 recall, 0 FP,
  identical to baseline** → M1 did not regress behavior.
